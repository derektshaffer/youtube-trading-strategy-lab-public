# Trading Pipeline Adversarial Test Contract

The normal Trading Intelligence CI gate runs `python -m pytest -q`. This is
intentional: the repository contains both `unittest.TestCase` suites and
function-style pytest tests. Running only `unittest` silently skipped many of
the causal market-feature and predictive-model adversarial cases.

The scenarios below form the minimum regression contract for the v6 pipeline.
They are synthetic or bounded historical replays; none require live provider
credentials.

| Scenario | Protecting tests | Contract |
| --- | --- | --- |
| Momentum breakout | `test_market_features.py::test_tight_base_breakout_is_labeled_consolidation_expansion`, `test_market_features.py::test_breakout_quality_distinguishes_hold_from_single_break` | A true expansion/hold is detected from completed bars. |
| Pullback and rebound | `test_market_features.py::test_pullback_quality_uses_depth_higher_low_and_volume_contraction`, `test_youtube_strategy_engine.py::BacktestTests::test_pullback_strategy_requires_pullback_then_breakout` | A pullback must have causal structure and a later trigger, not just a price dip. |
| Multiple bounces | `test_market_features.py::test_three_confirmed_bounces_can_flag_deterioration`, `test_market_features.py::test_bounce_is_not_counted_before_following_high_is_confirmed` | Bounces are confirmed without repainting and their sequence quality is preserved. |
| Failed breakout / reversal | `test_market_features.py::test_breakout_quality_flags_latest_failure_after_break`, `test_market_feature_validation.py::test_bearish_detector_inverts_directional_return` | Failed structure is distinguished from a holding breakout and measured in the declared direction. |
| Low-volume false positive | `test_market_features.py::test_pullback_quality_uses_depth_higher_low_and_volume_contraction`, `test_market_detector_gate.py::test_broad_but_unreliable_detector_is_mixed_not_eligible` | Volume quality remains explicit and an unreliable detector cannot be promoted merely because it fires. |
| Extreme RVOL from dormant baseline | `test_trading_auto_research.py::EmaOpportunityDiscoveryTests::test_extreme_rvol_from_dormant_baseline_is_audited_not_ranked_as_event` | A tiny historical baseline cannot manufacture a discovery winner. |
| Forward/reverse split and other reset actions | `test_youtube_strategy_engine.py::ProviderTests::test_corporate_actions_extract_split_collections`, `test_youtube_strategy_engine.py::ProviderTests::test_split_safe_raw_rows_restart_at_latest_split`, `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_batched_bars_trims_pre_split_history_and_records_integrity` | Raw-price research restarts at the latest corporate-action boundary. |
| Delisted/inactive stocks | `test_trading_auto_research.py::AutonomousResearchTests::test_catalog_sample_reserves_space_for_inactive_symbols`, `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_stale_active_data_is_explicit_but_old_inactive_history_is_allowed` | Historical membership includes inactive assets while active-symbol staleness still fails closed. |
| Missing bars and stale data | `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_stale_active_data_is_explicit_but_old_inactive_history_is_allowed`, `test_trading_auto_research.py::ValidationIntegrityRegressionTests::test_missing_or_stale_fixed_candidate_data_fails_closed_explicitly` | Missing evidence is named and cannot be converted to negative strategy evidence. |
| Partial intraday session | `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_current_partial_new_york_session_is_excluded`, `test_trading_market_discovery.py::MarketDiscoveryTests::test_strategy_preparation_drops_current_partial_five_minute_bucket` | Historical results are stable throughout the day and incomplete candles never enter a decision. |
| Extended-hours activity | `test_youtube_strategy_engine.py::BacktestTests::test_extended_hours_can_trade_at_reduced_size`, `test_youtube_strategy_engine.py::RuleTests::test_filters_out_extended_hours` | Extended-hours behavior follows the frozen settings and cannot leak into regular-only tests. |
| Sparse strategies | `test_market_detector_gate.py::test_sparse_directional_detector_cannot_be_promoted`, `test_trading_validation_core.py::ValidationStrengthTests::test_sparse_walk_forward_activity_caps_robustness` | Thin evidence cannot receive a strong or promotable label. |
| Intraday signal with weak daily proxy | `test_trading_auto_research.py::DiscoveryFallbackTests::test_fallback_unblocks_strategy_when_strict_daily_proxy_has_zero_matches`, `test_trading_auto_research.py::DiscoveryFallbackTests::test_strict_candidates_rank_before_fallback_fillers` | Discovery favors recall, but fallback provenance remains visible and strict candidates rank first. |
| Isolated profitable parameter point | `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_failed_neighbor_is_missing_evidence_not_broad_profitability`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_distant_finalists_are_not_mislabeled_as_local_neighbors` | One point, distant alternatives, or incomplete neighbor evidence cannot claim a robust neighborhood. |
| Broad profitable neighborhood | `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_profitable_external_neighborhood_requires_multiple_unseen_neighbors`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_broad_profitable_neighborhood_seeds_multiple_rule_values`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_only_complete_broad_profitable_neighborhood_seeds_execution_settings` | Multiple local configurations must survive the same unseen block before later folds can learn rule or execution-setting values. |
| Regime change helps adaptation | `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_regime_adaptation_is_only_better_when_score_and_pnl_both_improve` | Adaptive is declared better only if both unseen score and unseen P&L improve. |
| Regime change hurts adaptation | `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_harmful_regime_adaptation_reports_static_better`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_conflicting_regime_evidence_is_mixed_not_declared_a_win` | Harmful or conflicting adaptation is reported, not rationalized as added value. |
| Zero trades caused upstream | `test_trading_auto_research.py::ValidationIntegrityRegressionTests::test_walk_forward_failure_keeps_upstream_detail`, `test_trading_auto_research.py::ValidationIntegrityRegressionTests::test_retryable_provider_failure_records_stage_and_cooldown`, `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_non_symbol_provider_error_is_not_silently_swallowed` | Provider and walk-forward failures remain explicit, staged, retryable, and distinct from true inactivity. |
| Holdout contamination attempt | `test_trading_auto_research.py::AutonomousResearchTests::test_prior_autonomous_holdout_exposure_revokes_fresh_validation`, `test_trading_auto_research.py::AutonomousResearchTests::test_prior_cross_stock_exposure_revokes_fresh_validation`, `test_stock_strategy_finder.py::HoldoutReuseIntegrityTests::test_materially_reused_holdout_cannot_remain_validated` | Reusing an exposed anchor or cross-stock period revokes validation. |
| Future-data leakage attempt | `test_trading_validation_core.py::WalkForwardSplitTests::test_session_embargo_is_never_used_for_training_or_external_test`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_each_fold_can_learn_only_from_unseen_folds_that_already_finished`, `test_market_features.py::test_future_bars_do_not_repaint_historical_feature_rows`, `test_trading_catalyst_core.py::CatalystPointInTimeTests::test_future_news_never_appears_on_earlier_bar` | Features, catalysts, optimizer inputs, embargoes, and adaptive learning remain causal. |
| Point-in-time universe contamination | `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_catalog_sample_never_uses_post_cutoff_current_screeners`, `test_trading_auto_research.py::HistoricalDataAndUniverseIntegrityTests::test_current_screener_is_labeled_research_only_when_catalog_fails` | Post-cutoff movers cannot select symbols for historical validation; a fallback universe can never validate. |
| Adaptive/static counterfactual fairness | `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_static_baseline_uses_same_folds_without_adaptive_seeds`, `test_trading_validation_core.py::AdaptiveWalkForwardTests::test_static_baseline_reuses_identical_no_learning_folds` | Both modes share boundaries and information, while identical inputs are computed once. |

Provider-authenticated Alpaca and GitHub persistence smoke tests remain a
separate evidence layer. Offline success does not claim those external systems
were reachable during the run.
